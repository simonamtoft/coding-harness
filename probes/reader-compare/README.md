# Bulk-reader model comparison

This **manual, paid, worker-only** experiment compares `openai-codex/gpt-6-luna` and `anthropic/claude-haiku-5-5`. It is separate from `probes/run.ts`: that runner scores parent-agent conduct, not a model substituted inside a pinned subagent. The team-facing result is [REPORT.md](REPORT.md); raw JSONL, stderr and per-run answers stay untracked under `probes/results/reader-compare/<batch-id>/`. Do not commit or forward raw records without inspecting them for secrets and local paths.

The runner uses the canonical `bulk-reader.md` body as its appended system prompt, then starts Pi in print/JSON/no-session/no-extensions mode with the canonical sandbox and secret-result guard, `read,grep`, and `--thinking low`. It selects each model with separate `--provider`/`--model` flags and does **not** edit the canonical agent, local overrides, or credentials. It does not invoke the parent `subagent` tool, read-routing hook, or an actual parent workflow. `cases.json` pins source SHA-256s and evidence locations; source drift stops the run. The batch id includes Pi version, cases, the agent body and selected runtime inputs. An offline scorer revision is recorded separately as `scoreVersion`, so saved raw trials can be rescored without pretending they ran under a different Pi version. To reproduce an existing batch, use its recorded Pi version; a different installed Pi version creates a new batch. Check the local installed brief and provider availability before starting. The worker must read the installed brief as its first tool call; that read is allowed in addition to the question's source files.

```bash
python3 -m unittest discover -s probes/reader-compare -p 'test_*.py'
python3 probes/reader-compare/run.py --dry-run
python3 probes/reader-compare/run.py --trials 10 --cap 5
python3 probes/reader-compare/summary.py <batch-id>
```

`--trials 1` is a smoke; a later `--trials 10` resumes the same batch. Model order alternates by repetition. The runner saves each completed attempt before starting another. It halts on missing reported usage, a provider error, timeout, or the reported-cost cap; after inspecting local evidence, `--retry-incomplete` preserves the failed attempt and retries that cell **once**. `--rescore` updates stored assessments offline after a scoring-rule correction, without repeating paid calls. When Pi has changed since a batch ran, use `--rescore --batch <batch-id>` to select its old records without launching that old model run under the new Pi version. The $5 cap is enforced on **reported** usage between requests and on streamed assistant completions; in-flight requests, missing telemetry, subscription billing and unreported provider charges cannot be bounded exactly by it. Do not treat the cap as an invoice limit.

## Scoring and audit

Each task has three atomic factual questions. The offline check looks for expected terms in each labelled answer **under Answered facts**, a citation to the requested source, and a source-bound labelled line or range no wider than 40 lines containing the key's lines. It separately checks first-read compliance, read/grep-only calls, source-only access and required answer sections. These are **rule-based candidates**, not validated semantic accuracy: a false answer could contain the expected words, a correct answer may cite a different valid line or format a correct range differently, and extra unsupported claims are not scored. The report distinguishes these proxy counts from an audit of source excerpts. Never claim a citation is accurate merely because its number is present in a response. Recheck all flagged answers and sample passing answers against the pinned source before sharing a report. Store audit notes without raw private transcript content in the shareable report.

Tasks cover a large source file, a large document that can hit the read tool's output cap, a small multi-file contract, and a decision ledger. The identical sources/questions are used for both models; results are paired by case and repetition. Each model may use a different number of turns and tokens. No external judge is used; the fact key lives next to the prompts and can itself be wrong. Public repository files may be present in model training data, and the child inherits the host's Pi instructions and provider environment. Results apply only to this version of the worker brief, source hashes, Pi, and provider/model selection. Worker-only costs are not evidence of parent savings.
